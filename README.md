# Лабораторна робота №4 — склад автозапчастин

Лабораторна робота №4 замінює цикли обчислень на Stream API та додає шість запитів до складу. Формат входу, звичайний звіт і `--warranty` не змінилися.

Консольний застосунок для аналізу залишків автозапчастин (курс «Кросплатформні засоби програмування», рівень 2, варіант №4). Застосунок перевіряє записи CSV, обчислює кількість записів, сумарний складський залишок, вартість запасів і найдорожчу деталь. Некоректні рядки не переривають обробку: номер рядка та причина додаються до звіту.

## Формат вхідного CSV

Файл кодується UTF-8. Кожен рядок має п'ять полів, розділених крапкою з комою:

```text
sku;name;stock;unitPrice;supplier
```

`sku` — артикул, `name` — назва деталі, `stock` — невід'ємне ціле число, `unitPrice` — невід'ємне скінченне число з десятковою крапкою, `supplier` — постачальник. Текстові поля не можуть бути порожніми. Порожній рядок вважається помилкою. Приклад даних: [data/input.csv](data/input.csv).

## Правила перевірки

- `sku`, `name`, `supplier` — не `null` і не порожні;
- `stock` — невід'ємне ціле число;
- `unitPrice` — скінченне невід'ємне число.

Об'єкт деталі з хибними значеннями створити неможливо: конструктор кидає виняток, а причина потрапляє до списку помилок звіту.

## Види деталей

Вид визначає артикул, тому окремого поля у CSV немає.

| Артикул | Підтип | Гарантійна вартість |
|---|---|---|
| без `-R` у кінці | `OriginalPart` | 5% ціни × кількість |
| закінчується на `-R` | `ReplacementPart` | max(3% ціни; 20 грн) × кількість |

Ключ `--warranty` виводить гарантійну вартість у консоль після звичайного звіту; файл звіту не змінюється.

## Запити до складу

| Запит | Операція |
|---|---|
| деталі із залишком менше 10 | `filter` |
| артикули | `map` |
| вартість запасу за виробником | `groupingBy` |
| статистика цін | `summarizingDouble` |
| топ-5: ціна спаданням, назва зростанням | `sorted`, `limit` |
| пошук за артикулом | `Optional` |

`--queries` виводить перші п'ять запитів, `--find <артикул>` — пошук. Регістр артикула враховується. Вивід іде лише в консоль, файл звіту не змінюється. Приклад даних: [data/queries.csv](data/queries.csv).

## Збірка та запуск

Потрібен JDK 21. Maven Wrapper автоматично завантажує Maven під час першого запуску.

```powershell
.\mvnw.cmd clean verify
.\mvnw.cmd package
java -jar target/kzp-bigun-1.0.0.jar
java -jar target/kzp-bigun-1.0.0.jar --input data/input.csv --output out/report.txt
java -jar target/kzp-bigun-1.0.0.jar --warranty
java -jar target/kzp-bigun-1.0.0.jar --input data/queries.csv --queries
java -jar target/kzp-bigun-1.0.0.jar --find TIM-008
java -jar target/kzp-bigun-1.0.0.jar --version
java -jar target/kzp-bigun-1.0.0.jar --help
```

На Linux/macOS для збірки використовуйте `./mvnw clean verify` та `./mvnw package`.
Без параметрів зчитується `data/input.csv`, а звіт записується в `out/report.txt` і одночасно виводиться в консоль. Версію задає `<version>` у `pom.xml`: під час збірки Maven підставляє її та номер збірки в `src/main/resources/version.properties`, тому локально `--version` виводить `1.0.0+local`.

## Структура

- `SparePart` — абстрактний базовий тип: спільні поля та правила, `fromCsv`, рівність за підтипом і артикулом.
- `OriginalPart`, `ReplacementPart` — підтипи з різною гарантійною вартістю.
- `PartKind` — вид деталі: підпис, визначення за артикулом, створення підтипу.
- `WarrantyReport` — звіт про гарантійну вартість для `--warranty`.
- `PartStreamQueries` — запити Stream API до складу.
- `QueryReport` — форматування запитів для `--queries` і `--find`.
- `StockValue` — record із загальною кількістю та вартістю запасу.
- `CsvParser` — перетворення помилки рядка на `ParseResult`.
- `InventoryFileReader` — читання UTF-8 файлу та накопичення помилок із номерами рядків.
- `InventoryStats` — обчислення показників варіанта.
- `ReportFormatter` — форматування звіту, незалежне від локалі.
- `Main` і `CliOptions` — обробка CLI та запуск програми.
- `src/test/java` — тести JUnit 5.
