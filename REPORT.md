## 2. Мета роботи

Мета роботи – пройти повний шлях від створення репозиторію й налаштування інфраструктури до версії простої консольної програми, яку можна відтворено зібрати й запустити на Windows, macOS та Ubuntu.

У результаті отримано консольний Java-застосунок, який збирається однією командою через Maven Wrapper, перевіряється тестами JUnit 5 і аналізатором SpotBugs та пакується у виконуваний JAR. Роботу програми перевірено на Windows.

## 3. Постановка задачі

Програма читає записи про деталі на складі, перевіряє кожен рядок, обчислює показники й формує звіт. Вхідний файл `data/input.csv` має кодування UTF-8; один запис займає один рядок, поля розділено крапкою з комою:

```text
sku;name;stock;unitPrice;supplier
```

| Поле | Тип | Призначення та правило перевірки |
|---|---|---|
| sku | String | артикул, не порожній |
| name | String | назва деталі, не порожня |
| stock | int | кількість на складі, ціле невід'ємне число |
| unitPrice | double | ціна за одиницю, скінченне невід'ємне число |
| supplier | String | постачальник, не порожній |

Для коректних записів обчислюються чотири показники:

- кількість коректних записів;
- загальна кількість одиниць – сума значень `stock`;
- вартість запасу – сума добутків `unitPrice * stock`;
- найдорожча деталь – запис із найбільшим `unitPrice`.

Хибний рядок не зупиняє програму: до звіту додаються номер рядка та причина. Порожній рядок також вважається хибним.

## 4. Структура програми

Код розташовано в пакеті `com.bigun.kzp` за стандартною структурою Maven.

| Файл | Призначення |
|---|---|
| Main.java | точка входу, режими запуску, вивід у консоль і файл |
| CliOptions.java | розбір аргументів `--help`, `--version`, `--input`, `--output` |
| InventoryItem.java | один коректний запис про деталь |
| CsvParser.java | розбір і перевірка одного рядка CSV |
| ParseResult.java | результат розбору: запис або причина помилки |
| InventoryFileReader.java | читання файла в UTF-8, накопичення записів і помилок із номерами рядків |
| InventoryStats.java | обчислення чотирьох показників |
| ReportFormatter.java | формування тексту звіту з `Locale.ROOT` |
| VersionInfo.java | читання версії та номера збірки |

Потік даних від входу до звіту:

1. `Main` передає аргументи до `CliOptions` і отримує шляхи до файлів.
2. `InventoryFileReader` читає файл і передає кожен рядок до `CsvParser`.
3. `CsvParser` перевіряє рядок і повертає `ParseResult`.
4. `InventoryStats` обчислює показники за списком коректних записів.
5. `ReportFormatter` формує один текст звіту.
6. `Main` виводить цей текст у консоль і записує його у файл.

Лістинг 1 – розбір і перевірка рядка (фрагмент `CsvParser.java`):

```java
String[] fields = line.split(";", -1);
if (fields.length != 5) {
    return ParseResult.invalid("очікується 5 полів, отримано " + fields.length);
}

String sku = fields[0].trim();
String name = fields[1].trim();
String supplier = fields[4].trim();
if (sku.isEmpty() || name.isEmpty() || supplier.isEmpty()) {
    return ParseResult.invalid("назва, артикул і постачальник не можуть бути порожніми");
}

final int stock;
final double unitPrice;
try {
    stock = Integer.parseInt(fields[2].trim());
    unitPrice = Double.parseDouble(fields[3].trim());
} catch (NumberFormatException exception) {
    return ParseResult.invalid("ціна та кількість мають бути числами");
}
```

Лістинг 2 – обчислення показників (фрагмент `InventoryStats.java`):

```java
long stock = 0;
double value = 0;
for (InventoryItem item : items) {
    stock += item.stock();
    value += item.unitPrice() * item.stock();
}
Optional<InventoryItem> mostExpensive = items.stream()
        .max(Comparator.comparingDouble(InventoryItem::unitPrice));
return new InventoryStats(items.size(), stock, value, mostExpensive);
```

## 5. Інфраструктура

- **Maven.** `pom.xml` задає Java 21, кодування UTF-8, версію `1.0.0`, залежності та плагіни.
- **Maven Wrapper.** `mvnw` і `mvnw.cmd` дають змогу збирати проєкт без установленого Maven. У Git для `mvnw` задано право на виконання.
- **JUnit 5.** Бібліотека підключається з областю `test` і не копіюється в репозиторій.
- **SpotBugs.** Аналізатор запускається у фазі `verify` і зупиняє збірку, якщо знаходить дефект.
- **Виконуваний JAR.** `maven-jar-plugin` записує `com.bigun.kzp.Main` у маніфест. Під час роботи програма використовує лише JDK, тому JAR не потребує додаткових бібліотек.
- **Версія.** Maven підставляє `<version>` і `build.number` у `version.properties`; локально `--version` виводить `1.0.0+local`.
- **Правила репозиторію.** `.gitignore` виключає результати збірки, `.gitattributes` фіксує кінці рядків, `.editorconfig` – кодування й відступи.

```text
.\mvnw.cmd clean verify
.\mvnw.cmd package
java -jar target/kzp-bigun-1.0.0.jar --input data/input.csv --output out/report.txt
```

## 11. Відповіді на контрольні питання

1. **Яке призначення файла pom.xml?** Він описує Maven-проєкт: координати, версію Java, кодування, залежності та плагіни збирання.
2. **Чим відрізняються фази test, verify і package у Maven?** `test` компілює код і виконує модульні тести. `package` після тестів створює JAR. `verify` іде в життєвому циклі Maven після `package` і виконує додаткові перевірки, у цьому проєкті – SpotBugs.
3. **Навіщо потрібен Maven Wrapper?** Він завантажує визначену версію Maven, тому проєкт однаково збирається на різних комп'ютерах без установленого Maven.
4. **Яку роль відіграє метод main?** Із нього починається виконання програми; він отримує аргументи командного рядка.
5. **Чим примітивний тип відрізняється від String?** Змінна примітивного типу містить саме значення, а змінна типу `String` – посилання на незмінний об'єкт із методами. Посилання може бути `null`.
6. **Чому середнє потрібно обчислювати в double, навіть якщо сума й кількість мають тип int?** Ділення двох `int` є цілочисловим і відкидає дробову частину.
7. **Що станеться, якщо Integer.parseInt отримати рядок "abc"?** Виникне `NumberFormatException`. У програмі його перехоплює `CsvParser`, і рядок потрапляє до списку помилок.
8. **Чому не можна мовчки пропускати рядок із помилкою?** Користувач не дізнається, що частину даних не враховано, і сприйме неповний підсумок як правильний.
9. **Як String.split(";", -1) обробляє порожнє останнє поле?** Від'ємний ліміт зберігає порожні поля в кінці, тому їх кількість визначається правильно.
10. **Чому для шляхів краще використовувати Path.of, а не "data\\\\input.csv"?** `Path.of` використовує роздільник поточної ОС, а зворотна коса риска є роздільником лише у Windows.
11. **Навіщо явно задавати StandardCharsets.UTF_8?** Щоб українські символи читалися й записувалися однаково незалежно від системного кодування.
12. **Чим %n відрізняється від \n у форматованому виводі?** `%n` дає роздільник рядків поточної ОС, `\n` завжди дає символ LF.
13. **Які дані потрібно перевірити у вашому варіанті?** Чи рядок не порожній; наявність п'яти полів; непорожні артикул, назву й постачальника; цілий невід'ємний залишок; скінченну невід'ємну ціну.
14. **Які тести виявлять помилку в обчисленні середнього?** Тести з дробовим очікуваним результатом, наприклад сума 7 і кількість 2 мають дати 3.5. У варіанті №4 середнього немає, тому його показники перевіряє тест `calculatesAllIndicatorsForSeveralRecords`.
15. **Яке призначення статичного аналізатора?** Він шукає типові дефекти без запуску програми. SpotBugs аналізує скомпільований байт-код.
16. **Яку роль виконує GitHub Actions?** Автоматично запускає збирання й перевірки на серверах GitHub після змін у репозиторії, зокрема на різних ОС.
17. **Чим версія програми відрізняється від номера збірки CI і чому їх розділяє знак +, а не крапка?** Версія описує стан продукту, а номер збірки – конкретний запуск CI. За SemVer усе після `+` є метаданими, тоді як `1.0.0.42` не відповідає формату SemVer.
18. **Що має містити GitHub Issue на дефект?** Опис, кроки відтворення, очікуваний і фактичний результати.
19. **Що Ви повинні вказати у розділі звіту про академічну доброчесність?** Інструменти ШІ, ролі, запити, прийняті рекомендації, виправлені помилки та підтвердження розуміння коду.
20. **Яку роботу виконує агент DevOps, а яку – агент Валідатор?** DevOps допомагає з Maven, аналізатором, JAR і CI. Валідатор складає крайові випадки, перевіряє результати й оформлює дефекти.
21. **Який рядок вашої програми найскладніше пояснити і чому?** `result.error().ifPresent(error -> errors.add("Рядок " + lineNumber + ": " + error));` – у ньому поєднано `Optional`, лямбда-вираз і захоплення змінної `lineNumber`, яка має бути фактично незмінною.

## 12. Висновки

Створено першу версію консольного застосунку «Склад автозапчастин». Програма читає CSV у кодуванні UTF-8, відхиляє хибні рядки з поясненням, обчислює чотири показники варіанта №4 та виводить звіт у консоль і файл. Проєкт збирається через Maven Wrapper, перевіряється 13 тестами JUnit 5 і SpotBugs та пакується у виконуваний JAR.

У лабораторній роботі №2 запис `InventoryItem` буде замінено класом-сутністю `SparePart` із перевіркою в конструкторі та фабричним методом `fromCsv`, а підсумкові значення – записом `StockValue`, без зміни формату входу та звіту.
